# iPad mini 7 实机验收

本清单记录操作和预期，不代表已完成实机验收。本轮没有连接或部署 iPad。

## 1. 时间完整性

- 用含“6月16日晚10点27分进入，10点29分离开”的 OCR 整理。
  - 预期：两个独立事件保留到分钟；晚间换算为22:27/22:29，不丢时分。
- 用一张同时包含医院监控与城市监控、后半段3:10/3:24/3:26/3:45/4:42的 OCR 整理。
  - 预期：第二轮核对覆盖后半段；未覆盖项明确出现在待复核摘要，不能宣称全部核完。
- 分别录入仅日期、仅小时、具体分钟、含“约/左右”的时间。
  - 预期：保留原精度和约时，不补年份、分钟或未写出的事件。
- 点击任一建议或已确认事件的出处。
  - 预期：打开对应原照片，并显示原文摘录；多出处逐一可查看。

## 2. 增量、隔离与恢复

- 整理两张照片后，再点整理。
  - 预期：没有改动时不再调用模型，已有结果保留。
- 新增第三张；再修改第二张 OCR。
  - 预期：分别仅整理新增或修改的文字，不重发未改动线索。
- 中断批量处理后重试。
  - 预期：已完成条目从检查点恢复，只继续未完成条目。
- 两个剧本使用同名人物、相同编号与相同 OCR。
  - 预期：建议、出处、视图位置和撤销严格属于当前剧本。
- 两张照片记载同一明确事件，另有一张记载不同时间。
  - 预期：精确相同事件保留多个出处；不同时间分别保留，不猜测哪份为真。

## 3. 确认与撤销

- 在事件编辑中手动合并同一时间、不同表述的记录，再撤销。
  - 预期：合并保留全部出处和人物；撤销恢复两条原记录；不同时间不出现在合并选项中。

- 跨分类勾选人物、关系、事件后批量录入。
  - 预期：确认所选项；缺标题项目保留；没有二次补全年份或分钟的要求。
- 批量忽略或清除全部，然后撤销。
  - 预期：恢复上次建议；没有重复记录，也不恢复到其他剧本。
- 新增/删除关系、编辑/删除事件后撤销。
  - 预期：恢复原ID、出处及内容；后续内容已变更时阻止覆盖。
- 拖动人物后撤销；离开关系图再返回。
  - 预期：移动可撤销，返回保留该剧本的缩放与位置。

## 4. 讨论时查阅

- 点人物进入工作台。
  - 预期：在同一面板查看其事件、线索、手动关系；可进入另一人物或直接查看原文。
- 从工作台点事件定位时间线。
  - 预期：横屏居中选中，竖屏滚动至对应项，不出现被筛选隐藏的事件。
- 在时间线缩放/筛选、打开关闭详情，再横竖屏切换。
  - 预期：筛选不改变时间比例，保留视图，显示全部可找回所有事件。
- 原图放大后拖到四个边缘，旋转后继续拖动。
  - 预期：上下左右均可到达，不误触缩小，不选中文字。
- 长按人物拖向另一人，确认或取消关系输入。
  - 预期：目标恢复颜色；仅确认后保存；取消恢复正常状态。

## 5. 服务状态

- 在不同公网IP地区启动和返回应用。
  - 预期：CN选DeepSeek，其他明确地区选GPT；检测失败提示重试。
- 正常整理、第二轮核对失败、网络断开、额度不足。
  - 预期：状态灯和详情说明实际状态；仅断网/欠费使用本地回退；已完成结果保留。
- 本轮只做本地构建，不主动调用付费API或声称实机通过。


## 6. 本轮任务恢复与资料保护（待实机验收）

以下场景均为待验证操作和预期，本轮未连接 iPad，未执行真实 API 故障注入，不能视为已通过。

- 首轮 API 提取成功后，让第二轮核对失败，再点继续整理。
  - 预期：首轮人物、关系、事件、出处已保留；仅发起核对请求，不重新提取；线索显示核对失败原因及可重试状态。
- 首轮成功后，在核对过程中强制退出应用，再打开并继续。
  - 预期：恢复该剧本、该线索及原 OCR 对应的检查点，仅继续核对；已完成两阶段的线索不重复请求。
- 修改已留有检查点的 OCR，再继续整理；另测断网或额度不足后恢复服务。
  - 预期：旧原文检查点失效；修改后的 OCR 重新提取；本地回退记录可恢复 API 整理，已经人工确认的内容不被覆盖。
- 修改线索标题、OCR、备注但未正式保存，强退后重新打开。
  - 预期：提示恢复对应剧本、对应线索的草稿；恢复前不覆盖正式值；正式保存、放弃草稿后状态明确。
- 编辑、合并、忽略或删除后退出并重新打开，再撤销。
  - 预期：撤销记录持久保留，恢复原 ID、内容和出处；后续已修改或其他剧本的记录不会被覆盖。

## 7. 人物合并与回收站（待实机验收）

- 当前剧本至少有两个人物时，在人物工作台点击“合并人物”。
  - 预期：先选择合并对象并预览涉及的事件、关系、线索等关联；单人剧本不显示合并入口；未经确认不改变资料。
- 确认合并两个人物，再按姓名和旧别名筛选、查看关系图、时间线与线索。
  - 预期：保留人物承接完整关联，旧姓名保留为别名；重复关系妥善处理；图表没有失联节点，不涉及其他剧本。
- 合并后重启，再撤销合并。
  - 预期：恢复两个人物及原关联；合并之后有冲突修改时给出明确反馈，不静默覆盖。
- 删除线索、人物或事件，重启后从回收站恢复。
  - 预期：恢复完整资料及允许恢复的关联；原 ID、线索编号或关联记录已发生冲突时提示，不能覆盖现存内容。

## 8. 搜证轮次、记录对照与待确认分组（待实机验收）

- 剧本 A 切换当前搜证轮次并拍照，再切换剧本 B 拍照，再返回 A。
  - 预期：新照片自动使用各自剧本的当前轮次；重启后仍保留；两个剧本互不影响，“本轮”和“全部轮次”筛选准确。
- 从人物工作台的事件卡片点击“对照此记录”，选择第二条记录。
  - 预期：并排查看各自人物、时间精度、描述、原文与照片入口，不自动判定哪条为真；手动事件缺少出处时明确说明。
- 对这两条记录设置“待核对”或“已核对”，重启并切换剧本后再查看。
  - 预期：人工标记持久保留且按剧本隔离；两条记录及原出处保持完整。
- 查看待确认列表的“可直接录入”“需要补充”“需要核对”三组，并处理其中项目。
  - 预期：字段完整、缺字段、出处异常或核对失败的建议进入对应组；主按钮对应实际下一步；批量操作后计数和分组更新，支持按既定规则撤销。
